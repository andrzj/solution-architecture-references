Platform Engineering

Golden Paths

Pre-approved, documented paths for building and deploying services.

⏱ 10 min read

What it is

A golden path is an opinionated, fully supported workflow for a frequent engineering task — scaffolding a service, running CI/CD, or provisioning a standard environment — so the fastest way to work is also the compliant way.

Golden paths differ from raw platform APIs by encoding security, observability, and cost defaults into templates and shared pipelines rather than documenting optional checklists.

Why it exists

Without golden paths every team reinvents CI, Kubernetes manifests, and onboarding docs; security and reliability coverage becomes uneven.

Platform teams cannot scale human consultations; golden paths productise their expertise into self-service flows.

When to use

  • Tasks performed by three or more teams quarterly (new microservice, data pipeline, ML training job).
  • Backstage Software Templates or equivalent portal-driven scaffolding.
  • Shared GitHub Actions / GitLab CI workflows versioned by the platform team.

When not to use

  • One-off research spikes where experimentation should not be constrained.
  • Niche stacks with no platform owner — forcing a poor generic template is worse than explicit off-path process.

Typical architecture

Pros and cons

Pros

  • Cuts time-to-production from days to hours.
  • Embeds security scanning and SBOM by default.
  • Platform improvements roll out via template version bumps.

Cons

  • Templates rot without owners and quarterly refresh.
  • Over-prescriptive paths resist legitimate variation.
  • Authoring Backstage templates has learning curve.

Implementation notes

Shadow developers creating a new service before building the template. Ship v1 covering 80% of cases with documented escape hatches.

Measure adoption: % new repos created via template; interview teams that go off-path to learn gaps.

Common failure modes

  • Template drift: Teams fork template repo and stop receiving updates — publish templates from central repo with semver tags.
  • Mandate backlash: Forced golden path without quality drives shadow IT.

Decision checklist

  • Does each golden path have a named platform owner?
  • Are mandated controls (SAST, signing) separated from recommended linters?
  • Is escape hatch registration required for off-path services?

Example use cases

  • Python API path: Backstage template creates FastAPI repo, wires shared CI v3, provisions namespace and Grafana board in under five minutes.
