Security Architecture

Network Security Architecture

Designing layered network security: firewalls, WAF, IDS/IPS, VPC segmentation, PrivateLink, east-west traffic inspection, and Zero Trust Network Access.

⏱ 10 min read

What it is

Network security architecture designs north-south and east-west controls—perimeter protection, segmentation, encryption, and monitoring—for cloud and hybrid estates. At the edge, WAF and DDoS services filter HTTP abuse; inside the VPC, security groups (stateful, ENI-scoped) and NACLs (stateless, subnet-scoped) enforce default deny. NGFW and cloud network firewall products add deep inspection, TLS termination where policy allows, and IDS/IPS signatures on selected paths.

East-west traffic is service-to-service lateral movement; north-south is user or partner ingress. Historically teams hardened only the perimeter, which let an internal foothold roam freely. Modern designs pair VPC tiers, Kubernetes NetworkPolicies, service-mesh mTLS, and optional hub inspection VPCs with transit gateways. PrivateLink (and equivalents) keeps SaaS consumption off the public internet. Programmes aligned with Zero Trust still need these network controls—identity never replaces segmentation.

NIST SP 800-207 describes ZTNA as application-level per-session access brokered through a policy engine—not a VPN that grants subnet-wide reach. CIS Critical Security Control 13 maps to continuous vulnerability management at the perimeter and includes documenting which subnets may talk to which peers. OWASP guidance for web apps assumes an edge WAF on paths that accept untrusted HTTP.

Why it exists

Attackers continuously scan internet-facing assets. Flat internal networks let stolen VPN or SSO sessions pivot across subnets. Network architecture turns implicit trust into enforced paths so reconnaissance and lateral movement are slower and noisier. PCI segmentation, HIPAA technical safeguards, and similar frameworks expect documented enclaves and monitored boundaries.

DDoS, web exploits, and lateral movement remain among the most common incident patterns. A WAF can block injection attempts even when application code is still vulnerable, buying time for a fix. Correctly tiered VPCs force a compromised web instance through another security group before it can reach a database listener. VPC Flow Logs and NGFW telemetry surface anomalies that application logs miss.

Cloud threat research consistently ranks misconfigured security groups among the fastest paths from public internet to data stores. North-south controls buy time; east-west microsegmentation limits how far ransomware or cryptominers spread once a workload is compromised. Aligning flow-log retention with PCI, HIPAA, or FedRAMP expectations turns network telemetry into audit evidence, not only an IR afterthought.

When to use

  • Internet-facing applications and APIs that need edge scrubbing and WAF.
  • Hybrid cloud where corporate networks peer into production.
  • Multi-tier systems that separate presentation, logic, and data networks.
  • Regulated cardholder or PHI environments requiring isolated enclaves.
  • Zero Trust rollouts where east-west inspection limits lateral movement.

When not to use

  • Do not rely on perimeter alone—pair with identity, application authorisation, and segmentation.
  • Avoid complex hub-spoke designs before basic logging and IAM hygiene exist.
  • WAF as the only app control: WAFs have bypass and false-positive risks; they supplement validation and parameterised queries, they do not replace them.
  • IDS over TLS without an inspection policy: encrypted payloads need explicit TLS inspection (with privacy review) or monitoring shifts to endpoints and identity.

Typical architecture

North-south traffic passes edge WAF and DDoS scrubbing before segmented VPC tiers and monitored east-west paths.

Pros and cons

Pros

  • Edge WAF and DDoS protect availability and block common exploits.
  • Segmentation limits blast radius after an initial foothold.
  • Inter–security-group references are more maintainable than stale CIDR rules.
  • PrivateLink and private endpoints shrink internet exposure for admin and SaaS paths.
  • Flow logs and firewall telemetry feed IR and compliance evidence.

Cons

  • Rule sprawl without IaC review causes accidental openness.
  • East-west NGFW inspection adds latency and can bottleneck if undersized.
  • Encrypted traffic limits IPS visibility without careful TLS inspection policy.
  • PrivateLink endpoints add cost and operational overhead.
  • Misconfigured security groups remain a top cloud incident source.

Implementation notes

Place WAF and DDoS in front of public ALBs or CDNs; enable managed rule sets with custom exceptions tested in count mode before enforce. Design VPC tiers with separate subnets and security groups; default deny east-west except documented flows. Enable VPC Flow Logs and DNS query logging to a central security account.

Design security groups with least privilege: each group allows only the protocol and port required from a specific source—prefer referencing another security group over broad CIDR blocks. Never use 0.0.0.0/0 on ingress except public load balancers on 443. Start AWS WAF with the OWASP Core Rule Set in count mode for one to two weeks, tune false positives, then switch to block; add rate-based rules to auto-block IPs exceeding a threshold per five-minute window.

Use PrivateLink for SaaS consumption; broker admin access via SSM Session Manager or ZTNA instead of permanent VPN. Automate security group and NACL definitions in Terraform with policy checks in CI. For Kubernetes, enforce NetworkPolicies with a CNI that supports them (Calico, Cilium, Antrea). The default Kubernetes network is allow-all between pods; once a namespace has any NetworkPolicy, traffic not explicitly allowed is denied—define both ingress and egress policies for production workloads. Cilium with eBPF can enforce HTTP path-level rules (for example allow only GET /health) beyond IP and port.

Ship flow logs to a SIEM with alerts on denied connection spikes, unexpected east-west paths, and new outbound destinations. Document inspection points in architecture reviews so TLS decryption—where privacy policy permits—does not leave blind spots on encrypted lateral paths.

Common failure modes

  • 0.0.0.0/0 on admin ports: SSH or RDP from any IP is among the most scanned misconfigurations in cloud estates; bots find open ports within hours of exposure.
  • Database in a public subnet: Even with a restrictive security group today, one rule edit or attachment mistake publishes the listener to the internet—keep data tiers in private subnets with no internet gateway route.
  • Flat shared VPC: Multi-team shared networks let one compromised workload reach another tenant's data tier without crossing an inspection point.
  • WAF in log-only mode forever: Count mode is for tuning; leaving it permanent gives metrics without blocking—document a calendar exit to enforce mode.
  • No egress filtering: Inbound-only hardening still lets compromised instances beacon, pull payloads, and exfiltrate over outbound 443.
  • Peering transitive trust: Corporate LAN reach into production VPCs without an inspection hop recreates perimeter trust inside the cloud.
  • Overlapping NACL deny/allow rules: NACL rules evaluate in number order; a low-number allow can defeat a higher-number deny for the same flow—test rule ordering in staging.

Decision checklist

  • Are public endpoints behind WAF with documented rule exceptions?
  • Do data tiers lack internet routes and accept only application security groups?
  • Do security groups use inter-group references for internal traffic?
  • Are flow logs centralized and retained per policy?
  • Is admin access brokered without permanent VPN into production?
  • Are network rules defined in IaC with automated drift detection?
  • Was east-west reachability tested after the last major VPC change?
  • Is a WAF deployed in block mode on every internet-facing web property?
  • Is east-west traffic inspected via NGFW, mesh mTLS, or both?
  • Are Kubernetes NetworkPolicies deny-by-default for production namespaces?

Example use cases

  • Illustrative scenario — e-commerce edge: CloudFront, WAF, and Shield Advanced; origin in a private subnet behind an ALB only.
  • Illustrative scenario — PCI CDE: Segmented VPC; ASV scans hit the edge only; database subnet without an internet gateway route.
  • Illustrative scenario — hybrid ops: Direct Connect to an inspection VPC; egress via a centralized firewall.
  • Kubernetes zero-trust networking: Cilium NetworkPolicies with L7 enforcement—the payment service accepts only HTTP POST /charge from the order service.
  • Multi-tier web application: Public ALB in a public subnet; app tier security group allows 8080 only from the ALB group; database tier allows 5432 only from the app group—no path from the internet to the listener by design.
  • SaaS DDoS stack: Global CDN absorbs volumetric traffic; regional WAF rate-limits abusive IPs; origin sees only scrubbed HTTP.
