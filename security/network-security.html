Security Architecture

Network Security Architecture

Designing layered network security: firewalls, WAF, IDS/IPS, VPC segmentation, PrivateLink, east-west traffic inspection, and Zero Trust Network Access.

⏱ 10 min read

What it is

Network security architecture designs segmentation, filtering, and inspection so only intended traffic crosses trust boundaries. The key controls are: Security Groups (stateful, instance-level virtual firewalls — the primary control for AWS/GCP/Azure), Network ACLs (stateless, subnet-level — second line of defence, often used for explicit deny rules), WAF (Web Application Firewall — Layer 7, inspects HTTP request content, blocks OWASP top-10 attacks, SQL injection, XSS), and Next-Generation Firewall (NGFW) (inspects traffic at application layer with deep packet inspection, TLS termination/inspection, and IDS/IPS signatures).

East-west traffic refers to service-to-service traffic within a network (lateral movement), as opposed to north-south traffic (ingress from external users). Traditional network security focused almost exclusively on north-south (perimeter) traffic and did not inspect east-west traffic at all — allowing attackers who gained a foothold inside to move freely. Modern architectures address east-west through microsegmentation (Zero Trust network policies), service mesh mTLS, and in some cases, an internal NGFW or network inspection layer that all inter-service traffic passes through. AWS PrivateLink and equivalent cloud services allow applications to consume third-party or partner APIs over private network paths without traffic traversing the public internet, reducing the external attack surface.

Why it exists

Most compromise paths still traverse the network: volumetric DDoS, application exploits over HTTP, and lateral movement after initial access. Perimeter and segmentation controls buy time when application code is vulnerable—a WAF running OWASP Core Rule Set can block common injection patterns while teams ship fixes. NIST SP 800-41 treats firewalls and monitored boundaries as foundational; NIST SP 800-207 extends that to east-west flows in Zero Trust designs.

Flow logs, IDS telemetry, and service mesh mTLS expose patterns that application logs miss—beaconing, unusual east-west port use, and exfiltration over allowed egress. Network architecture is how architects make blast radius measurable instead of theoretical.

Design reviews should trace every inbound path to an owning security group or policy object so orphan rules are retired during refactors.

When to use

  • Every production VPC or equivalent landing zone with tiered subnets and default-deny posture.
  • Internet-facing properties where managed WAF rule sets complement secure coding and OWASP testing.
  • Regulated or high-sensitivity data paths requiring private service connectivity and no public datastore routes.
  • Zero Trust rollouts that must inspect and policy-bind east-west traffic, not only north-south edges.
  • Multi-account cloud estates where centralized egress inspection and shared services VPCs reduce duplicated perimeter tooling.
  • Partner integrations requiring private connectivity (PrivateLink, ExpressRoute, Cloud VPN) instead of exposing administrative ports.

When not to use

  • WAF as the only control—false positives and bypass techniques mean apps still need validation and parameterised data access.
  • Deep inspection without TLS strategy—encrypted payloads blind IDS unless termination or approved inspection architecture exists (with privacy review).

Typical architecture

North-south traffic passes CDN, DDoS scrubbing, and WAF before reaching private application tiers; data stores accept only security-group–referenced ports on private subnets without internet gateway routes.

Pros and cons

Pros

  • Tiered subnets and security-group references contain lateral movement after web-tier compromise.
  • Managed WAF packs provide OWASP-oriented coverage while code fixes are in flight.
  • Inter–security-group rules stay stable under autoscaling unlike brittle CIDR lists.
  • Private connectivity to PaaS APIs shrinks internet-exposed attack surface and audit scope.
  • Central flow and firewall logs feed SIEM detections when app logging is thin.

Cons

  • WAF tuning is continuous work—over-blocking harms revenue paths.
  • Hub-and-spoke inspection adds latency and capacity planning for east-west peaks.
  • Large estates suffer security-group sprawl without policy-as-code and graph analytics.
  • Private endpoints add per-AZ cost and lifecycle ownership.

Implementation notes

Model security groups as least-privilege tuples: protocol, port, source security group—avoid open admin ports on 0.0.0.0/0 except intentionally public HTTPS on load balancers. Ship VPC Flow Logs to immutable storage with retention aligned to NIST logging guidance. Roll out WAF in count mode, triage false positives on representative traffic, then enable block on validated rule groups including OWASP CRS. Pair rate-based rules with bot management for credential-stuffing storms.

In Kubernetes, enforce deny-by-default NetworkPolicies on ingress and egress; prefer CNIs that honor policies in production (Calico, Cilium, Antrea). Layer 7 rules (HTTP method/path) reduce over-broad allow lists. Document intentional east-west paths for auditors and map controls to CIS cloud benchmarks where required.

For hybrid connectivity, inspect traffic at transit gateways or dedicated inspection VPCs when regulatory language demands visibility into partner or on-prem paths. Pair DNS logging with firewall deny rules to detect command-and-control domains early. Review security-group and NACL changes through infrastructure-as-code pull requests with automated diff alerting, consistent with NIST configuration management expectations.

Validate WAF exclusions during every major application release—new JSON fields and mobile API shapes frequently reintroduce false negatives. Document allowed east-west flows in architecture decision records so future microservices do not silently widen internal attack surfaces.

Common failure modes

  • Data plane in routable public subnets—one overly permissive rule exposes databases globally.
  • Administrative exposure—SSH/RDP open to the internet remains a top scanner hit.
  • Eternal WAF learning mode—count-only configurations never enforce blocks.
  • Unrestricted egress—compromised instances phone home or exfiltrate freely.
  • NACL rule ordering mistakes—lower-number allows override intended denies.

Decision checklist

  • Are compute and data tiers on subnets without direct internet gateway paths?
  • Do internal rules reference security groups instead of drifting CIDR blocks?
  • Is production WAF blocking (not only counting) after tuning windows?
  • Are flow logs centralized, correlated, and retained for investigations?
  • Is east-west traffic governed by mesh mTLS, NGFW, or equivalent inspection?
  • Do clusters enforce default-deny NetworkPolicies for production namespaces?

Example use cases

  • Illustrative scenario — three-tier web app: Public ALB → private app tier (ingress only from ALB security group) → private data tier (database port only from app security group); no IGW route on data subnets.
  • Case study — edge DDoS and WAF: CDN and managed WAF rule sets (for example AWS WAF OWASP CRS) absorb attack volume and filter application exploits before origin load—pattern described in major cloud provider WAF guidance.
  • Illustrative scenario — Kubernetes microsegmentation: Cilium L7 NetworkPolicies allow only POST /charge from the order workload to the payment workload; all other pod traffic denied by default.
  • Illustrative scenario — SaaS egress control: Central egress proxy with TLS inspection policy exempting health-data subnets; VPC endpoints for KMS and secrets managers keep key material off the public internet.

Related patterns

  • Zero Trust Architecture — Policy-driven access replacing implicit east-west trust.
  • Defense in Depth — Network layer controls within layered programmes.
  • API Security — Application authorisation after traffic passes the edge.
  • Container Orchestration — Pod network policy in Kubernetes estates.
