Security Architecture

WAF & DDoS Protection

Defending internet-facing entry points from application-layer attacks and volumetric floods.

⏱ 10 min read

What it is

WAF & DDoS Protection is the pattern to use when internet-facing HTTP APIs and sites. Web Application Firewalls (WAF) inspect HTTP traffic for OWASP-style attacks; DDoS protection absorbs volumetric and application-layer floods before they reach origin infrastructure.

Example: AWS CloudFront + WAF blocks SQLi patterns, rate-limits login paths, and Shield Advanced mitigates a 200 Gbps L3/L4 attack while origin auto-scales within budget.

Why it exists

Public edges are probed continuously. Origin auto-scaling alone cannot stop application-layer abuse or costly volumetric attacks. Managed edge defenses add scrubbing, bot scores, and rule packs without patching every service.

When to use

  • Internet-facing HTTP APIs and sites.
  • Login and checkout paths needing stricter rate limits.
  • Compliance requiring managed rule sets (PCI).

When not to use

  • Pure internal east-west traffic — use mesh policy instead.
  • As sole authz — WAF complements, not replaces, app controls.

Typical architecture

Edge WAF and DDoS scrubbing before origin.

Pros and cons

Pros

  • Managed rule updates for new CVEs.
  • Rate limiting at scale without app changes.
  • Geo and ASN blocking for incident response.
  • Logging for forensic replay at edge.

Cons

  • False positives on JSON APIs.
  • Latency hop if not integrated with CDN.
  • Cost rises with request volume.
  • Complex rules become hard to test.

Implementation notes

Start with OWASP Core Rule Set in count mode, tune exclusions for APIs, then enforce. Pair WAF with origin rate limits and authentication.

Run game days simulating L7 floods; document runbook for enabling aggressive ACLs.

Common failure modes

  • Bypass via alternate hostnames not behind WAF.
  • Log-only forever — attacks unblocked.
  • Regex DoS from pathological rules.
  • Origin IP leak allowing direct attack.

Decision checklist

  • All public hostnames behind WAF/CDN?
  • OWASP CRS tuned with API exclusions?
  • Login endpoints rate-limited?
  • DDoS playbooks documented?
  • Origin addresses non-routable publicly?
  • WAF logs shipped to SIEM?

Example use cases

  • E-commerce: Bot control on checkout, CAPTCHA on abuse spikes.
  • Public API: Per-API-key limits plus geo allowlist for partners.
  • Media site: CDN caching absorbs flash crowds; WAF blocks scrapers.
