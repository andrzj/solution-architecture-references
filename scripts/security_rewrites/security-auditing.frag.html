What it is

Security auditing records security-relevant actions—authentication, authorization denials, administrative changes, data access—in tamper-evident stores so teams answer who did what, when, from where, with what result. Application events use a stable schema (actor, action, resource, outcome, correlation ID); cloud control-plane APIs supply the infrastructure half of the same timeline. CIS Control 8 (Audit Log Management) expects centralized collection, protected storage, and time sync; auditing feeds compliance and incident response.

Audit logging differs from debug logging: records are integrity-protected, retention-bound, and restricted from routine access. SIEM correlation and UEBA depend on reliable deny events, not only successes.

Why it exists

Without immutable centralized trails, breach scope is guesswork. SOC 2 CC7, PCI Requirement 10, and HIPAA §164.312(b) require logging and review. Denied access and failed MFA attempts are often the earliest credential-stuffing signals—omit them and mean time to detect suffers.

When to use

  • Production systems processing customer, financial, or regulated data.
  • Privileged IAM changes, KMS decrypt, schema migrations, break-glass access.
  • Export, sharing, bulk download, and admin impersonation features.
  • Multi-account clouds aggregating control-plane logs to a security account with WORM storage.

When not to use

  • Never log secrets, tokens, or full PII—use identifiers and references.
  • Do not collect without retention, access control, and legal-hold process.
  • Avoid duplicate incompatible formats that break correlation.

Typical architecture

Applications and cloud APIs emit structured events through streaming buffers into immutable object stores and SIEM indexes; long-term WORM archives satisfy retention and legal hold.

Pros and cons

Pros

  • Forensic timelines for scope and breach-notification decisions.
  • Continuous compliance evidence for access and change controls.
  • UEBA detects patterns invisible in single-system logs.
  • Accountability deters insider abuse when actions are attributable.

Cons

  • Volume and cost without tiering and retention discipline.
  • Clock skew complicates correlation—UTC and NTP required.
  • Sensitive fields in messages create secondary breach risk.
  • Alert fatigue if every audit line becomes a SIEM alert.

Implementation notes

Publish an audit schema contract; use append-only tables for high-value domains. Enable organization-wide cloud trails in all regions; deny delete on log buckets except break-glass roles. Correlate app, IdP, and cloud events with shared correlation IDs.

Map coverage to CIS logging guidance and framework matrices; test impossible-travel and bulk-download rules in exercises.

Common failure modes

  • Logs only on compromised host—centralize at ingest.
  • Mutable buckets—attackers erase trails.
  • Success-only auditing—denials omitted.
  • PII in payloads—audit store becomes sensitive data.
  • Retention shorter than audit period—Type II samples fail.

Decision checklist

  • Documented audit schema across services?
  • Control-plane logs all accounts and regions to a central sink?
  • WORM or Object Lock on log stores?
  • Retention meets legal and framework requirements?
  • Denials and admin actions captured?
  • SIEM detections exercised in tabletops?
