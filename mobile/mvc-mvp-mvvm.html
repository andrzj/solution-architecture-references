Mobile Architecture

MVC vs MVP vs MVVM

Comparing presentation-layer patterns for mobile apps with trade-offs.

⏱ 10 min read

What it is

MVC, MVP, and MVVM are presentation-layer patterns separating user interface from logic. Model-View-Controller (UIKit/Android classic) couples views and controllers tightly. Model-View-Presenter moves logic to presenters testable without UI.

Model-View-ViewModel (with data binding) exposes observable state from ViewModels to declarative UI (SwiftUI, Jetpack Compose).

Modern mobile apps often blend MVVM with unidirectional data flow (MVI) for predictable state.

Why it exists

Massive view controllers and activity God classes make mobile code untestable and hard to reason about.

Teams need a shared pattern for onboarding iOS and Android engineers.

When to use

  • New apps choosing architecture before feature velocity stalls.
  • Refactoring legacy MVC screens incrementally to MVVM.
  • Shared presentation logic between iOS and Android via common ViewModel contracts (KMP).

When not to use

  • Tiny utility apps where pattern ceremony exceeds benefit.
  • Forcing MVP on declarative UI stacks designed for MVVM.

Typical architecture

Pros and cons

Pros

  • Testable presentation logic off main thread.
  • Clearer separation for large teams.
  • MVVM pairs well with reactive UI frameworks.

Cons

  • Wrong pattern increases boilerplate.
  • Over-layering simple screens.

Implementation notes

Default new screens to MVVM with unidirectional state. Extract presenters/view models before adding third-party SDKs to UI layer.

See Mobile Architecture Patterns for broader context.

Common failure modes

  • Leaky ViewModel: Android context or UIKit types in ViewModel — breaks tests and lifecycle safety.
  • Binding loops: Two-way binding causes infinite updates — prefer single source of truth.

Decision checklist

  • Can presentation logic be unit tested without Robolectric/instruments?
  • Is navigation separated from ViewModel state?

Example use cases

  • Banking app: SwiftUI + MVVM; MVI for payments flow; 70% unit coverage on ViewModels.
